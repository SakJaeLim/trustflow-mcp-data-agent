# TrustFlow 3분 시연 대본

> 최종 코드 기준 자동 테스트는 49/49이다. 기존 영상에 37/37 또는 43/43이 보이면 최종 자막·설명란에서 49/49로 정정한다.

목표 길이: 2분 50초~2분 58초. 모든 화면은 1920×1080, 브라우저 확대 100%, 비밀값과 `.env`는 노출하지 않는다.

## 0:00-0:18 - 문제와 차별점

화면: 첫 화면, `30 questions`, `3 MCP tools`, `SERVER ACTOR ROLE analyst`.

멘트: “TrustFlow는 Company-X의 SQL·문서·관계 데이터를 세 MCP 도구로 연결합니다. 핵심은 언어모델의 계획을 바로 실행하지 않고 Typed QueryPlan과 PolicyGraph가 먼저 검증한다는 점입니다.”

## 0:18-0:45 - NL2SQL과 자동 보정

화면: `2025년 3분기 총 매출액은 얼마야?` 실행. `REPAIR`, `SQL_LIMIT_ADDED`, 표 근거를 차례로 확대한다.

멘트: “자연어는 명시적 SQL 계획이 됩니다. PostgreSQL AST와 허용 스키마를 검사하고, LIMIT가 없어도 외부 정책 래퍼가 최대 100행으로 강제합니다. 실제 실행은 9개 허용 테이블의 SELECT 전용 계정과 READ ONLY 트랜잭션을 사용합니다.”

## 0:45-1:12 - pgvector 문서 근거

화면: `Product-C1 설치 방법이 궁금해` 실행. `DOC-011`, verified answer, evidence ledger를 보여준다.

멘트: “40개 Markdown을 nomic-embed-text로 임베딩해 pgvector에서 검색합니다. 답변의 claim은 자신이 인용한 evidence만으로 검증되며, 근거 밖 식별자나 수치를 쓰면 결정적 답변으로 교체됩니다.”

## 1:12-1:35 - 지식그래프

화면: `Client-A가 사용 중인 제품 목록은?` 실행. 계획의 `graph.traverse`, `USES`, 경로 근거를 보여준다.

멘트: “133노드와 354관계에서 허용된 관계와 방향만 최대 2홉, 50노드 안에서 탐색합니다. 결과는 그래프 경로 evidenceId로 반환됩니다.”

## 1:35-2:10 - 실행 전 공격 차단

화면: `쓰기 공격 차단` 클릭. `DENY`, `DENIED`, evidence 0, `POL-PLAN-002`, `POL-SQL-001`을 보여준다. 이어 `민감필드 권한 차단`을 짧게 보여준다.

멘트: “삭제 의도와 DELETE AST는 실행 전에 DENY되고 실행 건수는 0입니다. 민감 열은 서버 역할로 판정하며, 필요한 승인은 사용자·역할·정확한 계획에 서명돼 5분 안에 한 번만 사용할 수 있습니다.”

## 2:10-2:37 - 로컬 LLM과 감사

화면: Gemma 평가 요약과 `audit:verify`의 `valid: true` 캡처를 번갈아 보여준다.

멘트: “처음 보는 표현은 로컬 Gemma 4가 JSON 계획을 초안하지만 같은 게이트를 통과합니다. 대표 의역 30건은 raw 도구 선택 93.3%, 정책 정규화 후 실행과 의미 정답 100%였습니다. 모든 종료 상태는 HMAC 서명 해시 체인과 별도 서명 checkpoint에 남습니다.”

## 2:37-2:58 - 정량 결과와 결론

화면: 평가 요약 카드.

멘트: “공개 공식 질문은 라우팅·실행·근거 연결 30/30, 정책 회귀 8/8, pgvector Hit@1 100%, 자동 테스트 49/49을 재현했습니다. TrustFlow는 MCP에 모델 독립적인 실행 통제, 근거 검증, 감사를 더한 온프레미스 데이터 에이전트입니다.”
