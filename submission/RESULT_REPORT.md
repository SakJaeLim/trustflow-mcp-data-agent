## 한 문장 요약

자연어 질문을 SQL·벡터·그래프의 Typed QueryPlan으로 바꾸고, PolicyGraph가 실행 전에 검증·보정·승인·차단한 뒤 근거 연결 답변과 서명 감사기록을 반환하는 온프레미스 MCP 데이터 에이전트다.

## 문제와 해결

기업 데이터 에이전트는 여러 검색 방식을 연결하는 것만으로는 부족하다. 모델이 만든 쓰기 SQL, 미등록 테이블 접근, 민감정보 요청, 과도한 검색이 실행될 수 있고 답변이 실제 원문에 근거했는지도 확인하기 어렵다.

TrustFlow는 모델 출력과 검색 문서를 모두 비신뢰 입력으로 취급한다. 모든 요청을 구조화된 QueryPlan으로 만든 뒤 다음 폐루프를 적용한다.

```text
질문 → 결정적 계획기/Gemma 4 초안(장애 시 safe fallback) → Typed QueryPlan
     → PolicyGraph PlanGate → ALLOW / REPAIR / APPROVAL_REQUIRED / DENY
     → 등록된 MCP 실행기 → EvidenceItem → 근거 제한 답변
     → HMAC 서명 해시 체인 + 별도 서명 checkpoint
```

## 과제 요구사항 충족

| 공식 요구 | 구현 |
|---|---|
| 관계형 데이터 자연어 질의 | `nl2sql` → AST 검증 → 읽기 전용 PostgreSQL |
| Markdown 문서 검색 | `vector_search` → nomic-embed-text 768차원 → pgvector HNSW |
| 관계 데이터 탐색 | `knowledge_graph` → 관계·방향·2홉·50노드 제한 |
| MCP 통합 | air 기반 서버가 위 세 도구만 노출 |
| 로컬 LLM | Ollama `gemma4:e2b` 계획 초안·근거 답변, 장애 시 fail-closed 계획·결정적 근거 답변 |
| 재현성·공개성 | 잠금 설치, SHA-256 데이터 설치, digest 고정 컨테이너, CI, SBOM |

## 독자 기여

1. 모델과 실행기 사이의 Typed QueryPlan을 기계 검증 가능한 신뢰 경계로 사용했다.
2. PostgreSQL AST 재귀 검사로 쓰기·시스템 카탈로그·재귀 CTE·whole-row projection·잠금·미허용 함수 우회를 차단한다.
3. 결과 행 수는 모델 SQL 내부 LIMIT와 무관하게 외부 정책 래퍼가 최대 100행으로 강제한다.
4. 민감 열 승인은 사용자·서버 역할·정확한 계획 해시에 결합하고, 5분 안에 한 번만 사용할 수 있다.
5. 각 claim이 실제 인용한 evidence만으로 식별자·수치를 검증하며, 불충분한 모델 답변은 결정적 답변으로 대체한다.
6. 도구 실행 전에 `started`, 종료 후 최종 상태를 HMAC 서명 해시 체인으로 기록한다. 별도 서명 head checkpoint는 원장이나 checkpoint 한쪽의 삭제·truncate·rollback을 탐지한다.
7. 공식 데이터 원본 ZIP과 추출 파일 전체를 설치·런타임·평가·적재에서 반복 검증하고, 각 근거에 검증된 dataset SHA-256을 연결한다.
8. PostgreSQL 업무 테이블과 pgvector 청크를 인증된 원본 스냅샷의 내용·세대·청크 해시와 대조한 뒤에만 런타임을 시작한다.
9. 제출 ZIP은 중앙/로컬 헤더·CRC·payload 중첩·완전한 manifest를 검증하고, 소스 생성 전과 최종 ZIP 승인 후 같은 비밀 검사를 수행한다.

## 한계와 운영 확장

- 공식 30문항은 재현성을 위해 결정적 계획을 사용하고, 자유 표현의 범용 품질은 Gemma 4 구조화 출력에 의존한다. 모델 장애 시 확인되지 않은 계획은 실행하지 않는다.
- 선행 CPU 실모델 계획 지연은 P50 22.818초, P95 41.008초였다. 7.2GB 모델은 다른 메모리 집약 프로그램과 동시 실행 시 로딩에 실패할 수 있어 GPU·소형 모델·캐시·전용 메모리가 필요하다.
- 웹 콘솔은 loopback 서버 고정 역할을 사용하지만 사용자 인증 시스템은 아니다. 외부 공개에는 OIDC/RBAC와 TLS가 필요하다.
- 메모리 지식그래프는 133노드 규모의 데모이며 대규모 성능을 대표하지 않는다.
- 원장과 checkpoint를 함께 삭제하거나 함께 교체할 수 있는 공격은 로컬 파일 경계 밖이다. 운영에서는 checkpoint를 독립된 WORM 저장소에 보관해야 한다.
